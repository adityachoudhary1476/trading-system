## 2. Architecture
```
FYERS → Market Data → MarketStore → FeatureEngine → MarketRegime
                                              ↓
                                    SignalCandidate (hypothesis)
                                              ↓
                                    AnalysisExplanation
                                              ↓
                          MarketReasoningProvider (wraps ModelProvider)
                                              ↓
                                        AIAnalysis (validated)
```
Provider-specific logic stays out of `research/intelligence.py`; the AI vendor is
decoupled via the existing `ModelProvider` abstraction (`LocalRuleModel`,
`OpenAICompatibleProvider`). The engine reads normalized OHLCV (+ instrument
metadata) only.

## 3. Feature engine
Reuses `indicators` primitives. `FeatureEngine.compute(df)` produces
`TechnicalFeatures` (causal, no look-ahead):
- **Trend:** SMA 20/50/200, EMA 20/50, price vs SMA20/50/200, EMA20 vs EMA50,
  trend classification (bullish/bearish/neutral from EMA cross + price vs SMA).
- **Momentum:** RSI 14, ROC (rate of change), momentum direction.
- **Volatility:** ATR 14, rolling std, annualized historical vol, vol regime
  (low/normal/high vs trailing median).
- **Volume:** volume SMA 20, relative volume, volume trend, unusual-volume flag.
- **Price structure:** recent high/low, distance from high/low, breakout &
  breakdown candidates (configurable lookback).

Insufficient bars => `insufficient=True`; SMA200/long-window stats are `None`,
never fabricated.

## 4. Derivative handling
`InstrumentClass` (equity/index/future/option_ce/option_pe/commodity_future).
`DerivativeFeatures` carries strike/expiry/underlying/option_type/days_to_expiry/
moneyness (filled from instrument metadata) and `open_interest`, `implied_vol`,
`delta/gamma/theta/vega`, `basis` — all `None` until FYERS supplies them. **No
fabricated OI/IV/greeks/basis.** Futures vs options and CE vs PE are separated by
`contract_id`; the engine never merges contracts.

## 5. Regime engine
`classify_regime(features)` → `MarketRegime(regime, confidence, supporting_features,
warnings)`. Combines trend + volatility axes (multi-feature, not single indicator).
Regimes: trending_up / trending_down / range_bound / high_volatility /
low_volatility / unknown. `confidence` bounded [0,1], explicitly an *analytical*
score, **not** a win probability.

## 6. Signal candidate
`SignalCandidate(symbol, contract_id, timeframe, direction, setup, confidence,
entry_context, invalidation_context, supporting_features, risk_flags, timestamp)`.
Directions: long/short/neutral. Setups: trend_continuation/breakout/breakdown/
mean_reversion/momentum/no_setup. Generated by `generate_signal_candidate`
(deterministic, no LLM). It is an analytical hypothesis; the report prints
"ANALYSIS ONLY — NO ORDER PLACED".

## 7. Explanation engine
`AnalysisExplanation(summary, bullish_factors, bearish_factors, neutral_factors,
risks, missing_data)` — splits evidence (what data shows) from uncertainty (what's
missing). `from_features` derives it from features + regime + candidate.

## 8. AI reasoning interface
`MarketReasoningProvider` wraps an existing `ModelProvider`. It builds a bounded
`AnalysisContext` (instrument/timeframe/regime/features/signal/recent_candles/
data_quality — never a raw DB dump), calls the provider, and translates the
validated `MarketView` into a strict `AIAnalysis` schema.
`AIAnalysis.from_model_json` **rejects** malformed output (pydantic validation;
confidence out of [0,1], missing `conclusion`, extra fields forbidden). Malformed
model JSON never silently becomes a valid-looking signal (`AnalysisRejected`).

## 9. Data-health gating
`MarketIntelligenceEngine.analyze(..., health_status=...)` returns
`{status:"BLOCKED", reason:"DATA_HEALTH = STALE"}` for stale/disconnected/auth_error/
invalid_data, and `NO_DATA` when the store has nothing. Insufficient history yields
a NEUTRAL candidate with `insufficient_history` risk flag — no fake indicators.

## 10. Look-ahead prevention
`FeatureEngine.features_at(df, ts)` slices data `<= ts` then computes; verified by
`test_no_lookahead_features_stable_to_future_spikes` (appending an extreme future
candle leaves features at T unchanged). Duplicate timestamps are dropped
(`keep="first"`) so a re-sent candle cannot overwrite a closed bar. Incomplete/
provisional candles are never treated as closed (the live pipeline already enforces
this; historical analysis only reads stored closed bars).

## 11. CLI usage
```
python -m trading_system analyze-history --symbols NSE:SBIN --timeframe 1d
python -m trading_system analyze-history --symbols NSE:SBIN,NFO:NIFTY25DECFUT --timeframe 5m
python -m trading_system analyze-history --symbols NSE:SBIN --timeframe 1d --ai local
```
Options: `--lookback`, `--ai {local,openai}`, `--as-of`. Prints REGIME, TECHNICAL
STATE, SIGNAL CANDIDATE, bullish/bearish evidence, risks, missing data, optional AI
conclusion, and "ANALYSIS ONLY — NO ORDER PLACED".
